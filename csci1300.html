01 / THE EXPERIENCE

A board game built for the terminal.

Each player chooses a lion and follows either the Cub Training or Pride Lands path. Turns combine movement, colored tile events, character statistics, advisors, and decisions that affect progress toward the finish.

  • Designed a complete two-player turn loop with clear menus and input validation.
  • Created distinct characters with pride, stamina, strength, and wisdom attributes.
  • Built two strategic paths with different starting benefits and advisor choices.
  • Loaded riddles, characters, and random events from external text files.

02 / GAMEPLAY

Choices shape every turn.

The menu keeps the game readable while giving players control over when to review their character, check their position, inspect an advisor, or move forward.

03 / ARCHITECTURE

Separate classes, connected systems.

I divided the game into classes so that each part had a focused responsibility. The main game loop coordinates those objects and updates the active player's state after each decision or event.

04 / WHAT I PRACTICED

Object-oriented design

Using classes, constructors, encapsulated data, and methods to represent the board, lions, advisors, and events.

Game-state logic

Tracking positions, statistics, turns, selected paths, character availability, and win conditions.

File input

Parsing character, riddle, and event data from text files instead of hard-coding every outcome.

Random systems

Selecting movement values, events, and riddles while keeping their effects connected to player state.

Input validation

Handling menu choices, full-line answers, capitalization, extra spaces, and repeated character selections.

Debugging

Tracing interactions between multiple systems and refining a large project across several source files.
