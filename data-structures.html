Dungeon Crawler
Data System.

A C++ dungeon-management program that combines three custom data structures to organize character inventories, rank items by damage, and calculate a route through a weighted dungeon graph.

01 / THE SYSTEM

Three structures, one connected problem.

The program treats each data structure as a specialized layer. Characters are located through a hash table, their inventories are ranked in priority queues, and those item values become weights in the dungeon graph.

  • Implemented a hash table with separate chaining and collision tracking.
  • Built a max-heap priority queue that ranks each character's items by damage.
  • Represented dungeon rooms and enemy connections as an undirected graph.
  • Connected the structures through a menu-driven program and file-based datasets.

02 / ITEM MANAGEMENT

Fast lookup meets ranked inventory.

Each hash-table node represents a character and contains that character's priority queue. Searching for a name finds the appropriate chain, while the max heap keeps the highest-damage item at its root.

03 / ROUTE LOGIC

Inventory data changes the graph.

Dungeon rooms become vertices and enemies label the edges between them. The program looks up each enemy's strongest item and uses its damage as the edge weight during Dijkstra-style distance relaxation.

04 / WHAT I PRACTICED

Hashing

Mapping character names to buckets, traversing linked chains, and measuring collisions.

Binary heaps

Maintaining a max heap through insertion, bubbling, removal, and recursive heapification.

Graphs

Building vertices and undirected edges from a file and storing adjacency relationships.

Pathfinding

Updating weighted distances across unsolved vertices using Dijkstra-style relaxation.

Dynamic memory

Managing arrays, linked nodes, pointers, graph vertices, and cleanup across custom classes.

System integration

Connecting multiple custom structures through shared character, item, and enemy data.
